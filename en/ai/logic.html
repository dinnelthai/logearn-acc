Strategy Logic: Writing the Decision Code

Basic Settings controls "when it triggers and how orders are placed on a hit"; Strategy Logic controls "whether you actually want it once it hits." This is a block of JavaScript — the platform loads data into ctx, and your code decides whether to let a token through or exclude it.

Pasting code replaces the whole block — it doesn't append. The editor always holds exactly one script. When you get new code, select all and delete the existing content before pasting — appending it below leaves two blocks of logic stacked on top of each other, which at best duplicates checks and at worst throws errors outright. Remember to click 保存策略 (Save Strategy) in the top right after editing.

The Strategy Logic tab. The row at the top shows this strategy's most recently matched tokens; below it is the code editor.

Common Patterns in the Code

Pattern What It Does
return false Excludes this token — it doesn't match. Every "veto" block in the screenshot returns false as soon as it finds a problem.
ctx.log.error(...) Writes a log line, viewable in the 实时日志 (Live Logs) tab. It's worth logging the reason and the actual values while excluding a token — otherwise once it's live you won't know why something didn't match.
|| {} and Array.isArray(...) A safety fallback before reading data. Some data sources aren't available under certain trigger methods (see the table below), and without a fallback this throws an error outright.

What's Attached to ctx

Data Source What's in It
ctx.chip_analysis Chip/holder distribution analysis. The screenshot uses above_percent, below_percent, and top5_holders (an array of the top five holders).
ctx.holders The holder list, an array — you can slice(0, 30) to get the Top 30. Each entry has address, total_hold_percent (share of holdings), and transfer_in_percent (share transferred in).
ctx.logearn LogEarn's own data; the screenshot uses token_address, mcap (current market cap), and max_up_mcap (all-time-high market cap).
ctx.kline_and_indicators K-line and technical indicators.
ctx.gmgn Data from GMGN.
Which data you can access depends on the trigger method. Signal-Triggered and Strategy-Triggered can use everything; Token Live-Stream-Triggered only has logearn and signals — writing ctx.holders or ctx.chip_analysis in a live-stream strategy gets you nothing, so those || {} fallback lines can't be skipped.

What the Code in the Screenshot Does

The official code is a classic "veto" pattern — it checks one thing after another, excluding a token as soon as it trips a red flag; only if it clears every check does it count as a match.

Check Logic
Blacklisted Address If a blacklisted address shows up in the Top 30 holders, exclude the token immediately.
Single Wallet Holding Too Much If any single wallet in the Top 5 by holdings has a share > 10%, exclude the token — this guards against a whale dumping.
Where the Top Holders' Tokens Came From If any Top 5 address has a transferred-in share > 5%, exclude the token. This requires the top holders' positions to have come mainly from buying, since a high transferred-in share suggests distribution or a rat-trading wallet.
Breaking Below the 0.86 Fib Level The low is fixed at 0, the high is the all-time-high market cap max_up_mcap, so the 0.86 retracement level = max_up_mcap × 0.14. If the current market cap breaks below this line, the token is blacklisted. It only looks at the current market cap, not the whole K-line history, so it won't wrongly exclude a token just because it "once broke below" that level in the past.
A gotcha built right into the code comments. The official team flagged the breakdown-blacklist block with a ⚠️: add_blacklist is a no-op under pure "Token Live Stream" mode — the code runs without erroring, but the blacklist entry is never actually written. If you're using Live-Stream-Triggered, go check the live logs after going live to confirm whether it's actually taking effect.
